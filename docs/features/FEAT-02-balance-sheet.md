# FEAT-02: Issuer Financial Statements & Balance Sheet (Итоговый баланс эмитента)

> **Feature ID:** `FEAT-02`  
> **Component:** `internal/provider/bfo`, `internal/domain`, `internal/service`, `internal/telegram`  
> **Priority:** P0 (Must Have)  
> **Target Cost:** $0.00 / month (Официальный API ФНС РФ bo.nalog.ru)  

---

## 1. Описание и User Story

**Как** осмотрительный инвестор,  
**Я хочу** видеть ключевые финансовые показатели эмитента (итоговый баланс, собственный капитал, чистый долг, выручку и прибыль),  
**Чтобы** быстро оценить платежеспособность компании и уровень долговой нагрузки без необходимости скачивать и читать 100 страниц МСФО.

---

## 2. Архитектура и интеграция с ГИР БО (ФНС)

В РФ все юридические лица сдают обязательную годовую бухгалтерскую отчетность в **ГИР БО (Государственный информационный ресурс бухгалтерской отчетности)**, администрируемый Федеральной налоговой службой (ФНС).  
Ресурс предоставляет открытый и бесплатный REST API.

- **Связка:**  
  1. Из MOEX ISS по ISIN получаем `emitent_inn` (ИНН эмитента, например `7708304940` для ПАО «ЕвроТранс»).
  2. Запрос в ГИР БО:
     ```http
     GET https://bo.nalog.ru/nws/api/v1/organizations/{INN}/financial-statements
     ```
  3. Получаем формы:
     - **Форма 1 (Бухгалтерский баланс):**
       - Строка `1600`: Итого активы.
       - Строка `1300`: Итого капитал и резервы (собственный капитал).
       - Строка `1410`: Долгосрочные заемные средства (кредиты и облигации > 1 года).
       - Строка `1510`: Краткосрочные заемные средства (кредиты и займы < 1 года).
       - Строка `1250`: Денежные средства и денежные эквиваленты (ДС).
     - **Форма 2 (Отчет о финансовых результатах):**
       - Строка `2110`: Выручка.
       - Строка `2400`: Чистая прибыль (убыток).
       - Строка `2330`: Проценты к уплате (для коэффициента покрытия).

## 3. Декомпозиция подзадач (Sub-tasks)

### `TASK-02-01`: Доменная модель `IssuerBalance`
- **Цель:** Представить ключевые показатели бухгалтерского баланса и отчета о прибылях/убытках.
- **Файл:** `internal/domain/balance.go`
- **Структура:**
  ```go
  package domain

  import "time"

  type IssuerBalance struct {
      INN              string    `json:"inn"`
      IssuerName       string    `json:"issuer_name"`
      ReportYear       int       `json:"report_year"`
      Standard         string    `json:"standard"`         // "РСБУ" или "МСФО"
      TotalAssets      float64   `json:"total_assets"`     // Итого активы (руб.)
      Equity           float64   `json:"equity"`           // Собственный капитал (руб.)
      TotalDebt        float64   `json:"total_debt"`       // Кредиты долгосрочные + краткосрочные
      CashEquivalents  float64   `json:"cash_equivalents"` // Денежные средства
      NetDebt          float64   `json:"net_debt"`         // Долг минус денежные средства
      Revenue          float64   `json:"revenue"`          // Выручка
      NetProfit        float64   `json:"net_profit"`       // Чистая прибыль
      DebtToEquity     float64   `json:"debt_to_equity"`   // Чистый долг / Капитал
      AuditorName      string    `json:"auditor_name"`     // Аудитор
      AuditOpinion     string    `json:"audit_opinion"`    // Заключение аудитора
      Source           string    `json:"source"`           // "ГИР БО (ФНС)"
      FetchedAt        time.Time `json:"fetched_at"`
  }
  ```
- **Критерий приемки (DoD):** Модель валидируется и поддерживает форматирование денежных сумм в млрд/млн ₽.

### `TASK-02-04`: Расчет финансовой устойчивости и коэффициентов
- **Цель:** Вычисление ключевых коэффициентов долговой нагрузки:
  - `NetDebt = (LongTermDebt + ShortTermDebt) - Cash`
  - `DebtToEquity = NetDebt / Equity`
- **Оценка риска по коэффициенту DebtToEquity:**
  - `<= 1.0`: 🟢 Низкая нагрузка (комфортный уровень).
  - `1.0 ... 3.0`: 🟡 Умеренная нагрузка.
  - `> 3.0` или `Equity < 0` (отрицательный капитал): 🔴 Высокая нагрузка (высокий риск дефолта).
- **Критерий приемки (DoD):** Тесты на расчет коэффициентов, включая случай отрицательного капитала.

---

### `TASK-02-05`: Кэширование финансовой отчетности (30 дней TTL)
- **Цель:** Исключить повторные запросы к серверу ФНС при частых запросах пользователями.
- **Файл:** `internal/store/memory/financials_cache.go` (и Firestore-адаптер для персистентности).
- **Параметры:**
  - Бухгалтерская отчетность не меняется в течение квартала.
  - TTL кэша: **30 дней**.
- **Критерий приемки (DoD):** Запрос баланса по тому же ИНН в течение месяца берется из кэша мгновенно (< 5 мс).
