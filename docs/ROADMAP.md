## 1. Введение и пользовательский контекст (User Need)

### Исходный фидбек:
> *«По отдельности можно все достать в интернете. Я бы хотел, чтобы всё можно было посмотреть в одном месте. Отчётность, но не всю, а только итоговый баланс-можно взять с сайта эмитента. Сообщения о существенных фактах тоже можно найти на сайте. Котировки, объемы можно найти в приложении брокера. Аналитику на сайтах брокеров, аналитических и аудиторских контор.*  
> *Все это будет входной информацией для анализа до принятия решения о действиях с бумагами.»*

### Проблема:
Инвестор тратит значительное время на проверку инструмента перед покупкой/продажей, переключаясь между 4–5 независимыми ресурсами:
1. Терминал / приложение брокера — котировки, стакан, текущий объем торгов, спред.
2. Сайт раскрытия информации (e-disclosure) / сайт эмитента — годовые/квартальные отчеты, поиск итогового баланса.
3. Лента существенных фактов — проверка на дефолты, оферты, созывы ВОСА/ГОСА, судебные иски.
4. Сайты рейтинговых агентств (АКРА, Эксперт РА и др.) и брокерская аналитика — кредитные рейтинги и аудиторские заключения.

### Цель решения:
Создать внутри Telegram-бота **«Единое окно принятия решений» (Decision Support Memo / Инвест-паспорт бумаги)**.  
Бот должен агрегировать и компактно представлять ключевые метрики в одном интерактивном сообщении с вкладками (Telegram Inline Keyboard), отвечая философии проекта: **100% бесплатные/публичные источники данных, нулевая стоимость инфраструктуры ($0/мес)**.

## 3. Источники данных и архитектура интеграции

| Блок данных | Источник данных | Протокол / Формат | Авторизация / Стоимость | Стратегия кэширования |
|---|---|---|---|---|
| **Котировки и объемы** | **MOEX ISS** (`iss/engines/stock/markets/bonds/securities/{SECID}`) | REST / JSON | Публичный (без ключа), $0 | 1–3 мин (в торговые часы) |
| **Итоговый баланс** | **ГИР БО (bo.nalog.ru API)** — Госинформресурс бухотчетности ФНС РФ | REST / JSON (по ИНН эмитента) | Официальный публичный API ФНС, $0 | 7–30 дней (квартальная отчетность) |
| **Существенные факты** | **e-disclosure.ru (Интерфакс-ЦРКИ)** / Новости MOEX | RSS / REST / HTML-парсер | Публичные ленты, $0 | 30–60 минут |
| **Кредитные рейтинги** | **Реестры агентств (АКРА, RAEX)** + Метаданные листинга MOEX | REST / JSON | Публичные данные, $0 | 7 дней |

> [!TIP]
> **Связующий идентификатор:** Связующим звеном между рыночными данными (ISIN/тикер) и корпоративными данными (баланс, факты, аудит) является **ИНН эмитента (`emitent_inn`)**. Он уже доступен в ответе `description` запроса MOEX ISS API.

## 4. Поэтапный план реализации (Action Items Roadmap)

### Фаза 1: Рыночные данные и ликвидность (Quick Win)
- [ ] **1.1. Модель данных:**
  - Создать структуру `domain.MarketData`:
    ```go
    type MarketData struct {
        LastPricePct   float64   // % от номинала
        LastPriceRub   float64   // в рублях
        YieldToMaturity float64  // YTM, %
        DurationDays   int       // Дюрация в днях
        VolumeTodayRub float64   // Объем торгов за сегодня в ₽
        TradesCount    int       // Количество сделок
        SpreadPct      float64   // Спред между лучшим спросом и предложением
        LiquidityTier  string    // "Высокая", "Средняя", "Низкая"
        UpdatedAt      time.Time
    }
    ```
- [ ] **1.2. MOEX Client:**
  - Расширить `internal/provider/moex/client.go`:
  - Добавить запрос к блоку `marketdata` для режима торгов `TQCB` / `TQOB`.
- [ ] **1.3. Форматтер и команда:**
  - Добавить отображение котировок, YTM и оборота в ответ команды `/bond <ISIN>`.
- [ ] **1.4. BDD-сценарий:**
  - Добавить тест в `features/bonds_on_demand.feature` на получение рыночной цены и объема.

---

### Фаза 2: Итоговый баланс эмитента (Бухотчетность)
- [ ] **2.1. Модель данных:**
  - Создать структуру `domain.IssuerBalance`:
    ```go
    type IssuerBalance struct {
        INN             string
        IssuerName      string
        PeriodYear      int
        PeriodType      string  // "Годовая (МСФО)", "Годовая (РСБУ)", "Квартал"
        TotalAssets     float64 // Итого активы
        Equity          float64 // Собственный капитал
        TotalDebt       float64 // Долгосрочные + краткосрочные кредиты/займы
        NetDebt         float64 // Чистый долг (Долг минус ДС)
        Revenue         float64 // Выручка
        NetProfit       float64 // Чистая прибыль
        DebtToEquity    float64 // Долг / Капитал
        AuditorName     string  // Название аудиторской компании
        AuditConclusion string  // "Положительное", "С оговорками"
        SourceURL       string
    }
    ```
- [ ] **2.2. Провайдер ГИР БО (ФНС) / e-disclosure:**
  - Реализовать клиент `internal/provider/bfo/client.go` для работы с публичным API `bo.nalog.ru`.
  - Метод `GetIssuerFinancials(ctx context.Context, inn string) (*IssuerBalance, error)`.
- [ ] **2.3. Кэширование:**
  - Реализовать сохранение в `internal/store` с TTL 30 дней (бухгалтерский баланс не меняется чаще раза в квартал).
- [ ] **2.4. Форматтер баланса:**
  - Вывод компактной выжимки (Активы, Капитал, Долг, Долг/Капитал, Выручка, Чистая прибыль).

### Фаза 5: Telegram UX — «Единое окно» (Decision Memo)
- [ ] **5.1. Интерактивная навигация (Inline Keyboards):**
  - Главная команда: `/memo <ISIN>` или кнопка `[ 📋 Полный инвест-паспорт ]` под `/bond <ISIN>`.
  - Кнопки переключения вкладок:
    - `[ 📊 Рынок & Стакан ]`
    - `[ 📑 Итоговый баланс ]`
    - `[ ⚠️ Существенные факты ]`
    - `[ 📅 График выплат ]`
  - Обработка `callback_query` с редактированием сообщения (`editMessageText`), чтобы не захламлять чат.
- [ ] **5.2. «Светофор инвестора» (Traffic Light Risk Indicator):**
  - Экспресс-индикаторы надежности:
    - 🟢 Низкий риск (Рейтинг ААА–А, Долг/Капитал < 1.0, чистый аудит, высокая ликвидность)
    - 🟡 Умеренный риск (Рейтинг ВВВ, Долг/Капитал 1.0–2.5, средняя ликвидность)
    - 🔴 Повышенный риск / ВДО (Рейтинг ниже ВВ, высокая долговая нагрузка, низкий объем торгов, свежие судебные иски/оферты)

## 6. Метрики успеха (Acceptance Criteria)

1. **Скорость ответа:** Полный профиль формируется менее чем за 800 мс (благодаря кэшированию фундаментала и параллельным запросам к MOEX ISS).
2. **Нулевая стоимость:** Все используемые API не требуют платных подписок и работают в рамках GCP Cloud Run Free Tier.
3. **Решение пользователя:** Инвестор получает исчерпывающую информацию для решения «брать/не брать» за 1 клик, не покидая Telegram.
